# Step 5 — Design Selection + Hero Variants 


---

## 0. Назначение блока

Пятый шаг pipeline. Council (в роли **Design Director**) выбирает **1, 3 или 5 контрастных** стилистических направлений из базы UI/UX Pro Max (юзер сам решает сколько), генерирует hero-screen на каждое с реальным копирайтом из Copy Brief, показывает юзеру. Юзер выбирает одно, Council собирает дизайн-систему под выбор.

**Входные данные:**
- Discovery Brief (Шаг 1) — тип продукта, аудитория, регион, **existing-design-extraction** (если был старый сайт), стек
- Custdev Synthesis (Шаг 3) — primary сегмент, барьеры, мотивы и профили симулированных персон
- Copy Brief (Шаг 4) — Hero (1 рекомендуемый + 2 альтернативы: H1, Sub-head, CTA), ToV, visual direction

**База ресурсов — файлы `data/*.csv` в этой папке (копия базы UI/UX Pro Max, MIT):**
- `styles.csv` — **88 стилей** (Best For / Do Not Use For / Conversion-Focused / Mobile-Friendly / Era / AI Prompt Keywords / CSS Keywords)
- `colors.csv` — **192 палитр** привязанных к типу продукта
- `typography.csv` — **74 пар шрифтов**
- `landing.csv` — **34 landing patterns** — **в этом шаге НЕ выбираем, это задача Шага 6**

**Выход:** N hero-вариантов (mockup + палитра + типографика + обоснование) → юзер выбирает 1 → Council собирает `design-tokens.json` + `component-library.md`. Landing pattern определяется в Шаге 6.

**Принцип:** варианты **контрастные**, не похожие. Разные стили, разные палитры. Каждый обоснован связкой с сегментом и ToV.

Или напиши „пропустить“ — тогда выберу из общих знаний и помечу результат `[без базы]`».* Никогда не выдавать выбор из головы за выбор из базы.

### 2.1 Если в Discovery есть existing-design-extraction

Council коротко советует и спрашивает:

>
> Стратегия:
> **A. Продолжить стиль** — варианты будут интерпретациями твоего текущего бренда (разные palettes/layouts внутри одного направления)

## 3. Автовыбор стилей — правила

### 3.1 Контрастность обязательна

Варианты отличаются **минимум по 2 измерениям из трёх**:
- **Температура:** холодный / тёплый / нейтральный
- **Энергия:** сдержанный / средний / энергичный
- **Эпоха:** modern-минимализм (2020s) / editorial/swiss (classic) / retro/brutalist/playful (non-mainstream)

Для N=5 добавляется 4-е измерение для различимости — **геометрия:** строгий грид / органика / хаос-асимметрия.

Для N=1 контрастность не нужна — Council выбирает один оптимальный стиль, аргументирует почему именно он.

### 3.2 Каждый стиль матчится с сегментом

Для каждого варианта Council прописывает обоснование:

> **Вариант A — «{название стиля}»**
> Почему подходит: {1-2 предложения, связка с профилем primary сегмента из Custdev Synthesis: возраст / культурный контекст / стиль решений / доверие}
> Почему ToV из Copy Brief работает: {1 строка}
> Риск: {1 строка — где может не выстрелить}

### 3.3 Фильтры из styles.csv

- **Best For / Do Not Use For:** enterprise B2B исключает «Playful vibrant»; creative portfolio исключает «Corporate Blue»
- **Conversion-Focused:** если цель = продажа/waitlist → минимум половина вариантов с уровнем `✓ High` или `◐ Medium`
- **Mobile-Friendly:** все варианты `✓ Good` или выше
- **Accessibility:** если сегмент 45+ или люди с ограничениями — минимум один вариант WCAG AA/AAA

### 3.4 Палитра под каждый стиль

По одной палитре из 192 (colors.csv), матч по «Product Type» из Discovery. Если тип не точно матчится — берётся ближайший и помечается в обосновании.

### 3.5 Типографика под каждый стиль

По одной паре из 74 (typography.csv). Выбор по «Era» стиля + «подход» из Copy Brief:
- educational + classic → serif headline + sans body (Playfair + Inter)
- direct sales + modern → sans + sans (Inter + Inter)
- playful + modern → display headline + sans body

### 3.6 Landing pattern — не здесь

Landing pattern (из 34 в landing.csv) выбирается в Шаге 6 на основе:
- Финальный Copy Brief с фиксированными Hero/value props/возражениями
- Количество релевантных блоков из Custdev Synthesis и Copy Brief
- Выбранный стиль из этого шага

В Шаге 5 не трогаем — оставляем Шагу 6 свободу решать под всю картину сразу.

### 3.7 Статус-маркеры

Показываем **только на тяжёлых операциях**, коротко. Два маркера:
- `→ подбираю контрастные направления`
- `→ генерирую hero-mockups ({N} штук)`

Всё остальное (чтение брифа, фильтры) — без маркеров, чтобы не шуметь.

## 4. Hero-mockup — формат зависит от LLM

Это важный момент. Council **адаптирует формат под платформу**, чтобы юзер визуально видел hero без лишних проблем:

### 4.1 Claude (web / desktop)

Council рендерит hero как **артефакт** типа `text/html` — отдельное окно сбоку, юзер видит реальный рендер (цвета, шрифты, layout). Не занимает контекст чата. Один артефакт на все варианты — тогда юзер сразу сравнивает; или по одному артефакту на каждый — если нужно больше места.

HTML в артефакте — минимальный inline CSS, один Hero-экран: H1 + Sub-head + CTA + placeholder для визуала (`<div style="background: linear-gradient(...)">[продуктовый скриншот]</div>`).

### 4.2 ChatGPT (web)

Аналогично — **Canvas** с HTML. Если Canvas не сработал — просит юзера нажать «Open in Canvas» или пишет явно «открой в canvas».

### 4.3 Gemini (web)

**Canvas** с HTML.

### 4.4 Perplexity и другие LLM без артефактов / Canvas

Fallback — **текстовый ASCII-wireframe** в чате (как в v1 черновика). Менее визуально, но работает везде:

```
┌────────────────────────────────────────────────────┐
│  [Logo]                              [Nav] [CTA]   │
├────────────────────────────────────────────────────┤
│                                                    │
│   {H1 — РЕАЛЬНЫЙ ТЕКСТ из Copy Brief}              │
│                                                    │
│   {Sub-head — РЕАЛЬНЫЙ ТЕКСТ}                      │
│                                                    │
│   [{CTA}]                                          │
│                                                    │
│                  [{направление визуала}]           │
│                                                    │
│   Палитра: ⬛ #XXX  ⬜ #XXX  🟧 #XXX                 │
│   Шрифты: Headline «{шрифт}» / Body «{шрифт}»      │
└────────────────────────────────────────────────────┘
```

### 4.5 Council сам определяет платформу

В начале Шага 5 Council спрашивает один раз (если ещё не знает из Шага 3):

> Какая у тебя LLM? (Claude / ChatGPT / Gemini / Perplexity / другая) — мне нужно знать, как показать hero: в артефакте / Canvas / текстом.

Если пользователь уже назвал свою LLM раньше — Council помнит и не переспрашивает.

## 5. Формат output — N hero-вариантов

### 5.1 Общая структура

```markdown
# Design Direction — {N} вариантов

[Вступление 3-5 строк: какой primary сегмент, какой ToV, какая стратегия — продолжить existing / сломать / с нуля]

---

## Вариант A — «{название стиля}» ({Conversion-Focused уровень})

### Обоснование (3 строки)
- Почему стиль матчится с сегментом «{имя}»: …
- Как ToV из Copy Brief звучит в этом стиле: …
- Риск: …

### Палитра ({номер в colors.csv}, «{Product Type}»)
- Primary / Secondary / CTA / Background / Text / Border — #XXXXXX
- Note из базы: {строка}

### Типографика ({номер в typography.csv})
- Headline: «{шрифт}» — {weight}
- Body: «{шрифт}» — {weight}
- Почему: {1 строка}

### Hero mockup
{артефакт HTML / Canvas / ASCII — в зависимости от LLM}

### Визуал Hero (направление)
{1-2 строки — скриншот продукта / иллюстрация / портрет ЦА / абстрактная графика / чистая типографика}

### Взаимодействия
{2-3 строки — hover, анимации, микроинтеракции из «Effects & Animation» в styles.csv}

---

## Вариант B — «{…}»
[тот же блок]

...

---

## Какой выбираешь?
- «A» / «B» / «C» / «D» / «E» — зафиксирую и соберу дизайн-систему
- «покажи ещё вариант» — дай направление (например, «editorial, но темнее»)
- «поменяй палитру в A» / «поменяй типографику в B» — точечная правка
- «перегенерируй все с акцентом на {характеристика}» — полный reroll
```

### 5.2 Размер output

- N=1: ~400-500 слов (один развёрнутый вариант)
- N=3: ~1000-1300 слов
- N=5: ~2000 слов

Оставляем как есть.

## 6. После выбора — сборка дизайн-системы

Юзер сказал «A» (или другой). Council собирает 2 артефакта (landing-pattern ушёл в Шаг 6):

### 6.1 `design-tokens.json`

```json
{
  "colors": {
    "primary": "#XXXXXX",
    "secondary": "#XXXXXX",
    "cta": "#XXXXXX",
    "background": "#XXXXXX",
    "text": "#XXXXXX",
    "border": "#XXXXXX"
  },
  "typography": {
    "headline": { "family": "...", "weights": [600, 700] },
    "body": { "family": "...", "weights": [400, 500] }
  },
  "spacing": { "base": "1rem", "scale": [0.5, 1, 1.5, 2, 3, 4, 6, 8] },
  "radii": { "sm": "4px", "md": "8px", "lg": "12px", "full": "9999px" },
  "shadows": { "sm": "{из стиля}", "md": "{…}", "lg": "{…}" },
  "breakpoints": { "mobile": "375px", "tablet": "768px", "desktop": "1024px" }
}
```

### 6.2 `component-library.md`

**Одна рекомендация** (не сравнение 2-3) под выбранный стиль и стек из Discovery:

```markdown
## Рекомендуемая библиотека: {одна библиотека}

**Почему:** {1-2 строки — связка со стилем и типом продукта}
**Установка:** {команды}
**Какие компоненты понадобятся:** Button, Card, Input, Dialog, Tabs, Accordion (FAQ), Toast
**Что НЕ использовать из библиотеки:** {если что-то противоречит стилю}
```

Маппинг стиль × стек → библиотека (внутренняя логика Council):
- Next.js + Tailwind + modern minimal / editorial → **shadcn/ui**
- HTML + Tailwind + playful / bold color → **DaisyUI**
- Кастомный дизайн (brutalist / experimental) → **HeadlessUI**
- Богатые микроинтеракции → **Framer Motion** (+ к любой выше)
- Accessibility-critical (45+, импаирменты) → **Radix UI**
- Consumer-app стиль → **NextUI**
- Framer (визуальный) → готовые Framer-компоненты, библиотека не нужна
- Webflow (визуальный) → готовые Webflow-компоненты, библиотека не нужна

### 6.3 Статус-маркер

Один:
- `→ собираю design-tokens + component library`

## 8. Учёт предыдущих шагов — связка

### 8.1 Если Discovery показал стек
Council в `component-library.md` матчит рекомендацию с указанным стеком. Если стек не указан — рекомендует исходя из стиля и технического уровня пользователя.

### 8.2 Если Copy Brief дал visual direction для Hero
Council подставляет placeholder в каждый hero-mockup: `[product screenshot]` / `[portrait photo]` / `[abstract illustration]` / `none (чистая типографика)`. Реальная картинка — задача юзера вне этого продукта.

### 8.3 Если гипотезы Custdev Synthesis не проверены
Council помечает их в обосновании `[не проверено]` и не выдаёт дизайн-решение за подтверждение гипотезы.

### 8.4 Если Copy Brief отметил мультиязычность
Council выбирает палитру и типографику с поддержкой нужных скриптов (Latin / Cyrillic / CJK). Избегает «designer typefaces» без кириллицы/азиатских глифов.

## 10. Оптимизация токенов

- Hero-варианты компактны (~300-400 слов каждый для N=3, ~400-500 для N=1, ~400 для N=5)
- Mockup в артефакте / Canvas — не ест контекст чата (на Claude / ChatGPT / Gemini)
- ASCII fallback простой (7-10 строк)
- Design-tokens.json — компактный, не 50 полей
- Component library — одна рекомендация, не сравнение
- Landing pattern не выбирается здесь — экономия ~200 слов output по сравнению с v1
- Статус-маркеры короткие, только на тяжёлых операциях
- При reroll — Council меняет только запрошенное, не всё
