# Landing Pipeline — полный цикл создания лендинга с LLM

Набор промтов, правил и чек-листов, который проводит от «есть идея продукта» до черновика лендинга, подготовленного к живой браузерной проверке и деплою. Полный режим работает в Claude Code как набор скиллов. Оркестратор можно использовать в Claude, ChatGPT, Gemini или Perplexity, но возможности веб-поиска, файлов и визуальной проверки зависят от платформы и тарифа.

> **EN summary.** A research-first landing-page pipeline for LLM agents: discovery → verifiable review synthesis → clearly labeled synthetic hypotheses from 10 simulated personas and a critic pass → copy brief → design direction from a real style database → landing generation → SEO/GEO, mobile, PageSpeed, and optional single-file multilingual. Step prompts are in Russian; the orchestrator exists in both languages (`00-orchestrator/ORCHESTRATOR-EN.md`).

## Схема цикла

```
Шаг 0  Ресерч идеи (опционально, внешние скиллы)
       есть ли рынок, какой сегмент, GO / NARROW / PIVOT
                 │
                 ▼
Шаг 1  Discovery intake ─────────── discovery-brief.md
       8 вопросов о продукте, ЦА, регионе, цели лендинга, конкурентах
                 │
                 ▼
Шаг 2  Парсинг живых отзывов ────── reviews-synthesis.md
       доступные проверяемые голоса из разных типов источников,
       задачи / барьеры / триггеры переключения / язык боли
                 │
                 ▼
Шаг 3  Синтетический кастдев ────── custdev-synthesis.md
       10 персон на языке живых отзывов, интервью о прошлом выборе,
       второй проход критиком, топ-5 болей и барьеров, мотивы
                 │
                 ▼
Шаг 4  Copy Brief ───────────────── copy-brief.md
       primary сегмент, primary барьер и мотив, Hero (H1 + подзаголовок + CTA),
       value props, обработка возражений, тон голоса на 3 осях
                 │
        ┌────────┴────────┐
        ▼                 ▼
Шаг 5  Выбор дизайна     Шаг 6  Сборка лендинга
       1 / 3 / 5 контрастных       landing pattern из 34, автовыбор стека,
       направлений из базы:        7 критических правил, legal-документы
       88 стилей, 192 палитры,     по региону, формы без бэкенда
       74 пары шрифтов
       → design-tokens.json
        └────────┬────────┘
                 ▼
Шаг 7  Polish Layer
       7a SEO/GEO + schema.org      7b Mobile (375 / 768 / 1024, CWV)
       7c PageSpeed (авто-фиксы)    7d Мультиязычность — всегда ПОСЛЕДНЕЙ,
                                       один HTML: главный язык индексируется,
                                       остальные — переключатель для людей
                 │
                 ▼
       launch-checklist.md → DEPLOY.md → проверка в живом браузере
```

Подробно по шагам, входам и выходам — [PIPELINE.md](PIPELINE.md).

## Два способа запуска

**A. LLM-чат, один стартовый промт.** Скопируй целиком `00-orchestrator/ORCHESTRATOR-RU.md` (или `-EN.md`) в первое сообщение нового чата. Модель сама переключает 5 ролей (Research Director → Copy Lead → Design Director → Landing Generator → Polish Layer) и после каждого шага делает паузу-чекпоинт. На Шаге 5 она попросит прикрепить пять CSV из `05-design/data/` — так выбор стиля идёт из базы, а не из памяти модели. Если платформа не умеет создавать файлы или Canvas, сохраняй каждый артефакт вручную по указанному пути.

**B. Claude Code.** Установи блоки как скиллы:

```bash
git clone https://github.com/x-bizarre/landing-pipeline.git
cd landing-pipeline
./install.sh
```

Появятся `/landing-pipeline` (весь цикл) и `/landing-discovery` … `/landing-polish` (отдельные шаги). В этом режиме модель читает базу дизайна, правила и чек-листы прямо из файлов.

Установщик не перезаписывает существующие одноимённые скиллы без подтверждения. Сначала можно проверить действия командой `./install.sh --dry-run`; для обновления с резервной копией — `./install.sh --force`.

**Память проекта.** Каждый лендинг живёт в своей папке по шаблону `project-template/`: артефакты шагов лежат файлами, `STATUS.md` хранит статус, решения и допущения. Новая сессия начинается с «открой STATUS.md и продолжай».

Короткий трек, если исследование уже есть и нужен только лендинг: `alt/landing-from-product-report.md`.

Первый запуск и ограничения платформ — [QUICKSTART.md](QUICKSTART.md). Карта между шестью шагами вебинара и расширенным публичным пайплайном — [WEBINAR-MAP.md](WEBINAR-MAP.md).

| `TOOLS.md` | Внешние скиллы и сервисы, которые усиливают шаги 0, 5 и 7 |
| `install.sh` | Установка блоков как скиллов Claude Code |
| `recipes/` | Практические рецепты из вебинара: UTM-редиректы, A/B-тест и квалифицирующая форма |
| `SECURITY.md` | Работа с недоверенным веб-контентом, секретами и персональными данными |

## Принципы, встроенные во все блоки

- **Сначала данные, потом тексты.** Копирайт строится на проверяемых цитатах из живых отзывов. Синтетические интервью дают только гипотезы и никогда не используются как отзывы, доказательства или якобы реальные customer quotes.
- **Синтетика помечается.** Каждый файл кастдева начинается с плашки «это симуляция, проверять живыми интервью». Персоны говорят языком отзывов, двое из десяти не покупают, второй проход вычищает лесть.
- **Никаких выдумок.** Нет данных — ставится `[FILL: …]` с инструкцией, что подставить. Стиль не из базы — помечается `[без базы]`.
- **Anti-AI-slop.** Запрещённые фразы, эмодзи, стоковые градиенты и «три колонки везде» вычищаются на уровне правил.
- **Hero отвечает на главный барьер.** H1 — формула «результат + несмотря на барьер», 5–10 слов.
- **Мультиязычность только в конце.** Перевод во время разработки ломает тексты; переводится утверждённая версия, главный язык остаётся индексируемым.
- **Проверять в живом браузере**, а не по HTTP-кодам: PageSpeed, прокрутка, мобильные брейкпоинты, форма, события аналитики. Балл Lighthouse не гарантируется заранее: он зависит от контента, сторонних скриптов, сети и устройства.
